# Стиль кода SkyW (плотный код)

Основание: `AGENTS.md` разделы 1.4 и 4.9. Конвенция применяется ко всему
коду в `src`, `tests` и `tools`. Язык кода — C# latest (net10.0).

## Общее правило

Плотность важнее воздуха: пустая строка — разделитель смысла, а не
оформление. Пустая строка оправдана там, где она отделяет типы или методы;
всё остальное пишется слитно с комментарием из 1–2 слов для групп
связанных свойств.

## Базовые правила

- Пустые строки отделяют только типы и методы. Между полями, между
  однострочными свойствами и внутри метода пустых строк нет.
- Блоки свойств разделяются одной пустой строкой и комментарием из
  одного-двух слов (`// Частота и шаги`).
- **Пустая строка перед заголовком** нужна тогда, когда безымянная группа
  членов (без комментария) предшествует группе с заголовком. Например,
  чтимые защищённые поля идут слитно, а следующая именованная группа
  отделяется пустой строкой:
  ```csharp
  private readonly ILogSink[] _sinks;
  private readonly bool[] _disabledSinks;
  private readonly Lock _writeLock = new();
  private LogLevel _minimumLevel;

  // Приёмники из фабрик принадлежат журналу, переданные в конструктор — нет.
  private bool _ownsSinks;
  private bool _disposed;
  ```
- Любая конструкция, открывающая блок, с единственным оператором пишется
  одной строкой без скобок: `if`, `for`, `foreach`, `while`, `do`,
  `using`, `lock`, `fixed`. Пример: `if (!IsEnabled(level)) return;`.
- Одно выражение в теле метода, аксессора или свойства — expression-bodied
  член (`=>`), а не блок с `return`.
- `checked`/`unchecked` блоком требуют скобок по грамматике C#: для одного
  выражения пишется форма `checked(...)`/`unchecked(...)`.
- Если тело не помещается в одну строку — обычный вид Microsoft: условие,
  скобка на новой строке, тело с отступом.
- Primary constructor используется, когда тело конструктора сводится
  к присваиваниям: нестатический тип, ровно один конструктор. Валидация,
  выделение памяти и побочные эффекты остаются в обычном конструкторе.

## Примеры

```csharp
// Хорошо: поля и свойства подряд, группы — комментарием.
public sealed class EngineOptions
{
    // Частота и шаги
    public int SimulationRateHz { get; set; } = 60;
    public int MaxStepsPerFrame { get; set; } = 8;

    // Потоки и каналы
    public ThreadingMode Threading { get; set; } = ThreadingMode.Multi;
    public int BatchBytes { get; set; } = 256 * 1024;
}
```

```csharp
// Хорошо: primary constructor без тела.
public readonly struct VisualId(int index, int generation) : IEquatable<VisualId>
{
    public int Index { get; } = index;
    public int Generation { get; } = generation;
}
```

```csharp
// Хорошо: однострочный if и lock.
if (!IsEnabled(level)) return;
lock (_writeLock) return _count;
```

## Пустые тела

- Конструктор без тела (включая делегирующий на `this`/`base`), метод или
  интерфейс с пустой реализацией пишется с телом `{ }` на строке
  объявления:
  `public EngineLog(params ILogSink[] sinks) : this(LogLevel.Information, sinks) { }`.
- Если цепочка наследования базового конструктора или список интерфейсов
  слишком длинны, их переносят на несколько строк, оставляя `{ }` на
  последней:
  ```csharp
  public EngineLog(params ILogSink[] sinks)
      : this(LogLevel.Information, sinks) { }
  ```

Комментарий объясняет **почему**, а не пересказывает **что** делает код;
максимум две строки. XML-документации (`<summary>`, `<remarks>` и другие)
не пишутся. Подробность explanations живёт в `docs/` и в отчётах `log/`.

## Интерфейс или класс

Достаточно одного условия для введения интерфейса: граница проекта или
слоя, подмена в тестах, сокрытие внешней библиотеки, точка расширения
для чужого кода. Одна реализация в том же проекте — конкретный класс.
